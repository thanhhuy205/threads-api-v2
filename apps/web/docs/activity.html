Activity Notifications QA spec

Activity page tracks account notifications. The nav should show a red unread dot by default when unread notification data exists. After the user opens Activity, all notifications should be marked as read and the red dot should disappear.

02

Unread Red Dot

Expected Behavior

  • Navbar calls GET /notification/unread when the user is authenticated.
  • If data.isNotification is true, the Activity nav icon shows a red dot.
  • If the user has never opened Activity and unread data exists, the red dot should be visible by default.
  • When the user clicks Activity, the app calls POST /notification/read and the red dot should be cleared after success/refetch.
03

Notification Types

Circle Invitation

  • Type: INVITATION.
  • Card opens invitation detail modal.
  • Target circle id should be visible when provided.

Post Interactions

  • Types supported by current card: LIKE, REPLY, QUOTE, MENTION.
  • REPLY đang là notification tương ứng với comment/reply trên bài viết.
  • Click should route to target post when publicId can be resolved.
  • Card should show actor, count aggregation and post preview text.

Share And Repost

  • Types exist in app model: SHARE and REPOST.
  • Expected QA behavior: show interaction-style card and route to target post.
  • Current routing should be checked because ActivityItem does not yet route SHARE or REPOST into PostInteractionNotificationCard.

Post And Message

  • Types exist in model: POST and MESSAGE.
  • Current Activity card switch does not have dedicated cards for these two types, so they should fall back to FallbackNotificationCard.
  • Verification covers fallback copy, timestamp, actor avatar and click target via targetType.

Target Type Coverage

  • Known target types include POST, USER, CIRCLE, REPLY, COMMENT, MESSAGE and FOLLOW.
  • resolveTargetPath currently maps only post, user and circle targets.
  • Reply/comment/message targets either use fallback behavior or get explicit route mapping when backend returns them.

Follow

  • Type: FOLLOW.
  • Card routes to actor profile or target user profile.
