Cursor Pagination Flow (Friend Requests)

Luồng Cursor Pagination an toàn: Frontend chỉ truyền ID của user (sender/receiver), Backend tự ghép thành Composite Key để truy vấn trang tiếp theo. (Tương tự với danh sách "Sent" nhưng tráo đổi vị trí ID).

Potential Issues

Race cond.
2 request follow đồng thời có thể tạo 2 record Follow. Giải pháp: unique constraint (followerId, followingId) trong DB + upsert thay vì check-then-create.
Count drift
followersCount trên User có thể sai nếu increment/decrement fail sau khi update Follow. Giải pháp: wrap trong transaction hoặc dùng background job recount định kỳ.
Friend vs Follow
Hệ thống hiện là follow 1 chiều. Thêm friend request tạo 2 model quan hệ. Cần quyết định: friend = mutual follow hay friend = accepted request? Khuyến nghị: friend = accepted request, auto follow khi accept.
Spam
User có thể spam follow/unfollow liên tục. Cần rate limit (ví dụ max 30 follow/phút) dùng Redis sliding window hoặc bảng AntiSpam có sẵn.
Feed impact
Khi accept friend → feed FRIENDS_ONLY cần hiện bài user mới. Nếu dùng fan-out-on-write, cần enqueue bài cũ vào feed mới. Nếu fan-out-on-read thì chỉ cần update relationship cache.
Transaction
Chấp nhận / Từ chối lời mời (PATCH): Hàm handleFriendRequest sử dụng Prisma Transaction (transactionService.doInTransaction) để đảm bảo tính toàn vẹn dữ liệu. Chuỗi hành động: Tìm ID người gửi từ username → Kiểm tra lời mời có tồn tại không qua cặp (senderId, receiverId) → Cập nhật trạng thái thành ACCEPTED hoặc REJECTED. Toàn bộ được bọc trong 1 transaction, nếu có lỗi ở bất kỳ bước nào, data sẽ tự động rollback.
Pagination
Lưu ý CỰC KỲ QUAN TRỌNG về biến after (Cursor Pagination) cho Friend Requests:
Hệ thống thiết kế KHÔNG DÙNG ID tự tăng (Auto-increment ID) của bảng FriendRequest làm cursor nhằm bảo mật (tránh bị ID enumeration/cào data). Thay vào đó, cursor là ID của User trong cặp quan hệ:
  • GET /me/friend-requests/received: (Lời mời bạn nhận được). Giá trị after phải là ID của người gửi (senderId) của record cuối cùng ở trang hiện tại.
  • GET /me/friend-requests/sent: (Lời mời bạn đã gửi). Giá trị after phải là ID của người nhận (receiverId) của record cuối cùng ở trang hiện tại.
Khi nhận được after, Backend sẽ tự động dùng nó kết hợp với ID của người đang đăng nhập để tạo ra composite cursor { senderId_receiverId } query trực tiếp vào Database rất nhanh và an toàn. Frontend Developer cần chú ý truyền đúng giá trị này khi làm tính năng "Load more".
