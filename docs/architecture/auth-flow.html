Architecture · Authentication & Authorization

Luồng xác thực và phân quyền

Trang này giải thích hệ thống biết bạn là ai bằng JWT/refresh token và quyết định bạn được làm gì bằng role/middleware.

Cơ chế xác thực

Hệ thống dùng JWT access token để chứng minh user là ai. Refresh token là chuỗi random, được hash rồi lưu DB. Khi logout, access token hiện tại được đưa vào blacklist Redis để middleware chặn lại.

Luồng đăng nhập

Mỗi mũi tên là một lần gọi thật trong kiến trúc route → controller → service → repository/worker.
1

Client gửi login/password.

2

Service tìm user và compare bcrypt password.

3

Service đọc role, sinh token pair, lưu refresh token hash kèm session metadata.

4

Client dùng access token trong Authorization và refresh token trong x-refresh-token.

Luồng refresh token / session renewal

Client gửi raw refresh token trong header x-refresh-token. Server hash token, tìm record DB, reject nếu revoked/expired, revoke token cũ, rồi sinh token pair mới cùng sessionId.

Luồng đăng xuất

Logout cần cả access token và refresh token. Service set Redis blacklist cho access token trong 15 phút và revoke refresh token trong DB nếu tìm thấy.

Đây là trust boundary chính: thiếu token, token blacklist, JWT invalid, user không tồn tại hoặc user BANNED đều bị chặn trước controller.

auth middleware rút gọn
const token = header.split(" ")[1];
const isBlacklisted = await redisService.exists(redisKey.auth.accessTokenBlacklist(token));
const decoded = await jwtService.verifyToken({ token });

Security checklist

  • JWT bearer required cho route protected.
  • Redis blacklist checked.
  • Refresh token stored hashed.
  • BANNED user blocked.

Điểm nguy hiểm

  • permission.ts hiện là stub.
  • Route upload avatar không có authorization.
  • Refresh token truyền bằng header.
