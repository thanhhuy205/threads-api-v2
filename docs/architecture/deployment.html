Architecture · Deployment

Triển khai và hạ tầng

Trang này mô tả cách app được build, chạy bằng Docker/Nginx và những service ngoài cần có.

Runtime và container

Dockerfile build TypeScript trong stage builder, chạy npm ci, Prisma generate và npm run build; image runtime chạy node dist/src/server.js. Worker dùng cùng image nhưng command npm run start:worker.

FileVai trò
DockerfileBuild production image Node 20 alpine.
docker-compose.ymlChạy api, worker, Redis và Nginx production-style.
docker-compose.provider.yamlChạy MySQL 8, Redis 8.6.2, RedisInsight và Nginx local.
nginx/conf.dReverse proxy vào API container.
.github/workflowsCI/deploy workflow của repository.
Database runtime: package dùng Prisma 7.8 và @prisma/adapter-mariadb; provider compose chạy MySQL 8. Cần giữ schema/connection config tương thích cả MySQL và MariaDB adapter.

Sơ đồ deploy

Màu cam là API server, màu xanh là worker xử lý phần nặng sau response.

Pipeline deploy

1

Push lên production hoặc dev kích hoạt workflow Build.

2

GitHub Actions build Docker image và push GHCR với tag SHA/production.

3

Nhánh production chạy job deploy trên self-hosted runner.

4

Runner tạo .env, pull image và tiếp tục deploy.

Key files

  • src/app.tsMiddleware stack và mount router.
  • src/server.tsRedis connect, server listen, repeat jobs.

Điểm chú ý

  • Redis fail làm app boot fail.
  • Một số service còn stub/mock và được đánh dấu.
  • Không revert dirty worktree hiện có.
