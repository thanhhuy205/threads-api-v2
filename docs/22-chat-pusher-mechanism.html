Cơ chế Pusher cho chat realtime trong threads-api-v2

TL;DR — Luồng đúng là: POST /message-groups/:publicId/messages lưu message vào DB trước, sau đó trigger Pusher event message:new lên channel private-chat-{groupPublicId}. FE subscribe channel này để nhận message realtime, còn lịch sử vẫn lấy từ API để chống miss event.

Flow gửi message end-to-end

Bạn đã có bước tạo tin nhắn rồi, nên phần cần thêm chỉ là đoạn phát event sau khi transaction commit thành công.

1 · REST nhận request gửi tin message-group.controller.ts

Client gọi POST /message-groups/:publicId/messages với body { content }. API đã xác thực JWT và lấy senderId từ req.user.sub.

2 · Lưu DB bằng transaction message-group-facade.service.ts

Service validate member của group, insert bản ghi Message, update lastMessageAt, rồi trả về payload message.

3 · Trigger Pusher event message-group-facade.service.ts

Sau khi transaction thành công, trigger event lên channel của cuộc trò chuyện. Nếu Pusher lỗi thì chỉ log, không nên rollback request đã gửi tin thành công trong DB.

4 · FE nhận event và cập nhật UI web/mobile client

FE subscribe đúng channel của group, bind event message:new, append message vào state nếu chưa tồn tại. Khi mở lại phòng chat vẫn gọi API GET /message-groups/:publicId/messages để đồng bộ.

Channel naming khuyến nghị

  • Chat group: private-chat-{groupPublicId} — chỉ member group được subscribe.
  • User riêng: private-user-{userId} — dùng cho notification cá nhân.
  • Event chat mới: message:new.
  • Event đã xem (phase sau): message:seen.
★
Không dùng public channel cho chat production vì ai biết channel name cũng subscribe được. Dùng private channel + endpoint auth để kiểm tra member.

// src/modules/message-group/service/message-group-facade.service.ts
import { pusherService } from "@/modules/pusher/service/pusher.service";

async sendMessage(groupPublicId: string, senderId: string, content: string) {
  const messageGroup = await this.findMessageGroupOrThrow(groupPublicId);
  await messageMemberService.assertMemberOrThrow(messageGroup.id, senderId);

  const messagePayload = await transactionService.doInTransaction(async (tx) => {
    const message = await messageService.createMessage(
      { messageGroupId: messageGroup.id, senderId, content },
      tx,
    );

    await messageGroupService.updateLastMessageAt(messageGroup.id, new Date(), tx);
    return mapMessageResponse(message);
  });

  try {
    await pusherService.trigger(
      `private-chat-${messageGroup.publicId}`,
      "message:new",
      {
        groupPublicId: messageGroup.publicId,
        message: messagePayload,
      },
    );
  } catch (error) {
    baseLogger.error("Failed to trigger chat realtime event: %o", error);
  }

  return messagePayload;
}

FAQ

Nếu Pusher lỗi thì có nên fail API gửi tin nhắn không?
Không nên. Message đã lưu DB là nguồn sự thật. Realtime chỉ là kênh phát nhanh cho UX.
Vì sao vẫn cần API get messages nếu đã có realtime?
Realtime có thể miss event khi user offline/reconnect. API history giúp đồng bộ trạng thái chuẩn.
Nên đặt event tên new-message hay message:new?
Chọn một convention và giữ nhất quán toàn hệ thống. Với repo này, pattern resource:action khá dễ mở rộng.
