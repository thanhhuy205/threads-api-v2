01

Runtime Stack

Job system dùng BullMQ cho queue/worker chính, Redis client cho một số data structure riêng, và QueueEvents để quan sát trạng thái job.

Producers

src/modules/job

Các class producer expose method enqueue job. Service gọi producer, producer gọi queue.add.

Workers

workers/*.ts

Mỗi worker tạo bằng createWorker, switch theo job.name, concurrency mặc định 3.

QueueEvents

queues/*.ts

Monitor waiting, active, completed, failed cho email/bloom/pinecone. Like chưa có QueueEvents file riêng.

Redis

redisQueueredisWorker

BullMQ dùng IORedis riêng. App cũng dùng redisService cho Bloom filter, blacklist, sets và Redis lists.

04

Like Pipeline Detail

Like là phần dễ đọc nhầm nhất vì có cả BullMQ producer và Redis list pipeline. Đây là mô tả hiện trạng, không phải đề xuất sửa.

Request path hiện tại

  • Like/unlike gọi PostService.like(publicId, userId, isLiked).
  • Service dùng Redis set post:<publicId>:likes để add/remove userId.
  • Nếu add/remove thành công, service tăng/giảm post:<publicId>:likeCount.
  • Service đẩy JSON vào list likes_add hoặc likes_remove.

Worker path dự kiến

  • LikeWorker.initSyncJob chạy processAddLike và processRemoveLike.
  • Mỗi processor gọi rPopCustomBatch(key, 500), group theo postPublicId.
  • Add path gọi likeRepository.createMany và postRepository.incrementLikedCount.
  • Remove path hiện cũng gọi createMany rồi decrementLikedCount; xem notes bên dưới.

07

Current Notes & Sharp Edges

Các ghi chú này phản ánh code hiện tại. Theo yêu cầu, tài liệu chỉ ghi lại để team nhìn rõ, không sửa behavior.

like worker

LikeProducer có initSyncJob repeat mỗi 5 giây, nhưng chưa thấy service/startup nào gọi method này. Nếu không enqueue job đó, processAddLike/processRemoveLike sẽ không chạy.

like batch

rPopCustomBatch gọi lMPop nhưng hiện trả về mảng results rỗng, chưa parse dữ liệu từ Redis response.

like remove

processRemoveLike hiện gọi likeRepository.createMany thay vì deleteMany, sau đó decrement count. Đây là behavior đang đọc được từ code.

sync-post-like

syncPostLike đọc rpop post:<publicId>:likes, trong khi request path đang dùng Redis set sAdd/sRem trên cùng key. Phần xử lý chính bên trong method đang comment nhiều.

queue events

QueueEvents dùng constructor mặc định chưa truyền connection từ redisQueue; nó sẽ dựa vào BullMQ default connection behavior.

constants

BLOOM_KEY.FILTER_USERNAME và BLOOM_KEY.FILTER_EMAIL có trailing spaces trong constant, nhưng worker/service hiện hard-code key không có trailing spaces.

email producer

CreateVerifyEmailProducer có userName, nhưng EmailWorker.sendVerificationEmail chỉ dùng email và token.
