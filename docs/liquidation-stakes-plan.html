The Liquidation Stakes — Hội nhóm có thời hạn và sự đánh đổi

Feature brief Phá vỡ tư duy "nhóm là vĩnh viễn". Mỗi nhóm được sinh ra với một lượng Năng lượng (Energy HP). Tương tác chất lượng nạp HP, sự im lặng rút cạn nó. Khi HP về 0, nhóm tự hủy vĩnh viễn. AI phân tích ngữ nghĩa để phân biệt "Deep Talk" vs rác. Giao diện lão hóa theo thời gian thực. Trước khi chết, nhóm để lại "Soul Stone" trong Viện bảo tàng Threads.

server/services/ai-judge.service.ts
const JUDGE_PROMPT = `
Bạn là bộ lọc chất lượng nội dung.
Chấm điểm đoạn text sau từ 0–10:
- 8-10: Tranh luận sâu, chia sẻ kiến thức,
  trải nghiệm cá nhân có giá trị
- 4-7: Góp ý bình thường, có nội dung
- 0-3: Spam, emoji đơn lẻ, "Chấm", "Hóng"
Chỉ trả về JSON: {"score": number, 
"reason": string}
`;

export async function judgePost(
  content: string
): Promise<{ score: number; hp: number }> {
  // Check content hash cache first
  const hash = sha256(content);
  const cached = await redis.get(
    `judge:${hash}`);
  if (cached) return JSON.parse(cached);

  const res = await llm.complete(
    JUDGE_PROMPT, content);
  const { score } = JSON.parse(res);

  // HP delta: Deep Talk +5, Parasite -1
  const hp = score >= 6 ? 5
           : score <= 2 ? -1 : 0;

  await redis.setEx(
    `judge:${hash}`, 3600,
    JSON.stringify({ score, hp }));
  return { score, hp };
}
server/cron/drain-energy.cron.ts
// Chạy mỗi giờ — node-cron "0 * * * *"
export async function drainEnergy() {
  // Lấy nhóm chưa có post trong 1 giờ qua
  const silentGroups = await prisma.group.findMany({
    where: {
      deletedAt: null,
      lastPostAt: {
        lt: new Date(Date.now() - 3_600_000)
      }
    },
    include: { energy: true }
  });

  for (const group of silentGroups) {
    const newHp = Math.max(
      0, group.energy.current - 5);

    await prisma.groupEnergy.update({
      where: { groupId: group.id },
      data: { current: newHp }
    });

    // Trigger kill nếu HP về 0
    if (newHp === 0) {
      await triggerGroupDeath(group.id);
    }
  }
}
server/routes/groups.ts — POST /:id/sacrifice
router.post("/:id/sacrifice", auth, async (req, res) => {
  const { karmaAmount } = req.body;
  const userId = req.user.id;

  // Validate user karma balance
  const user = await prisma.user.findUnique(
    { where: { id: userId } });
  if (user.karma < karmaAmount)
    return res.status(400).json(
      { error: "Không đủ Karma" });

  // 1 Karma = 10 HP, max 50% HP hồi/lần
  const hpGain = Math.min(
    karmaAmount * 10, 500);

  await prisma.$transaction([
    prisma.user.update({
      where: { id: userId },
      data: { karma: { decrement: karmaAmount } }
    }),
    prisma.groupEnergy.update({
      where: { groupId: req.params.id },
      data: { current: { increment: hpGain } }
    }),
    // Hạn chế đăng bài 48h
    prisma.userRestriction.create({
      data: { userId, type: "POST_LIMIT",
              expiresAt: new Date(
                Date.now() + 172_800_000) }
    })
  ]);
  res.json({ hpGain, newKarma:
    user.karma - karmaAmount });
});
server/services/soul-stone.service.ts
export async function generateSoulStone(
  groupId: string
) {
  const group = await prisma.group.findUnique({
    where: { id: groupId },
    include: {
      posts: { orderBy:
        { qualityScore: "desc" }, take: 10 },
      members: { where: { isSacrificer: true } },
      energy: true
    }
  });

  const summary = await llm.complete(`
    Tóm tắt lịch sử nhóm này thành một đoạn
    văn bia ~100 chữ. Tập trung: đỉnh cao,
    lý do tử vong, di sản để lại.
    Data: ${JSON.stringify(group)}
  `);

  // Lưu Soul Stone, xóa mềm group
  await prisma.$transaction([
    prisma.groupSoulStone.create({
      data: { groupId, summary,
        peakHp: group.energy.peak,
        livedDays: calcDays(group),
        topPostIds: group.posts
          .map(p => p.id) }
    }),
    prisma.group.update({
      where: { id: groupId },
      data: { deletedAt: new Date() }
    })
  ]);
  await grantAshesBadge(
    group.members.map(m => m.userId));
}

DB Schema — Prisma + MySQL

6 table chính. GroupEnergy là trung tâm. Tất cả foreign key đều có index. Không normalize soulStoneSummary — lưu thẳng text.

prisma/schema.prisma — Group + GroupEnergy
model Group {
  id            String    @id @default(cuid())
  name          String
  description   String?
  adminId       String
  createdAt     DateTime  @default(now())
  lastPostAt    DateTime  @default(now())
  deletedAt     DateTime? // soft-delete

  energy        GroupEnergy?
  posts         Post[]
  members       GroupMember[]
  soulStone     GroupSoulStone?
  cprSessions   CprSession[]
  @@index([deletedAt, lastPostAt])
}

model GroupEnergy {
  id       String  @id @default(cuid())
  groupId  String  @unique
  current  Int     @default(1000)
  max      Int     @default(1000)
  peak     Int     @default(1000)
  // percent: computed on read

  group    Group   @relation(
    fields: [groupId], references: [id])
}

model PostQualityLog {
  id         String   @id @default(cuid())
  postId     String   @unique
  score      Float    // 0–10 from LLM
  hpDelta    Int      // +5, 0, -1
  createdAt  DateTime @default(now())
  @@index([postId])
}
prisma/schema.prisma — Sacrifice + SoulStone
model UserKarmaLog {
  id         String   @id @default(cuid())
  userId     String
  groupId    String
  karmaSpent Int
  hpGained   Int
  createdAt  DateTime @default(now())
  @@index([userId])
}

model UserRestriction {
  id        String   @id @default(cuid())
  userId    String
  type      String   // "POST_LIMIT"
  expiresAt DateTime
  @@index([userId, expiresAt])
}

model CprSession {
  id           String    @id @default(cuid())
  groupId      String
  activatedBy  String
  expiresAt    DateTime
  resolved     Boolean   @default(false)
  success      Boolean?
  createdAt    DateTime  @default(now())
}

model GroupSoulStone {
  id          String   @id @default(cuid())
  groupId     String   @unique
  summary     String   @db.Text
  peakHp      Int
  livedDays   Int
  topPostIds  Json     // String[]
  createdAt   DateTime @default(now())
  @@index([createdAt])
}

Risks & Mitigations

Risk
Sev
Mitigation
LLM chậm làm post bị delay — UX tệ khi user đợi score xong mới thấy bài.
HIGH
POST bài ngay, trả 202 Accepted. AI judge chạy async via queue (Bull/BullMQ). HP update sau khi judge xong. UI hiển thị "đang đánh giá" badge trong meantime.
Spam cùng nội dung để bypass AI judge — clone content để farm HP.
HIGH
Cache kết quả judge theo sha256(content) trong Redis 1h. Duplicate content nhận score = 0 → không cộng HP. Rate limit 3 posts/phút/user.
Race condition: 2 request sacrifice cùng lúc → karma trừ 2 lần hoặc HP cộng sai.
HIGH
Dùng prisma.$transaction với SELECT FOR UPDATE trên row karma của user. Chỉ 1 transaction thành công, cái còn lại rollback và trả 409 Conflict.
Cron drain chạy khi server restart → bỏ qua chu kỳ, nhóm không bị trừ HP đúng hẹn.
MED
Lưu lastDrainAt vào GroupEnergy. Khi cron chạy, tính số giờ bị bỏ qua và trừ bù. Dùng persistent cron (bull-board) thay vì in-memory cron nếu production.
Soul Stone generation gọi LLM mất 5–10s — user thấy nhóm "đã chết" nhưng museum chưa có.
MED
Soft-delete group ngay (nhóm biến mất). Tạo Soul Stone async trong background job. Museum page filter WHERE soulStone IS NOT NULL. Không ảnh hưởng trải nghiệm.
Glitch UI quá nặng trên mobile — filter + blur CSS làm chậm máy yếu.
LOW
Detect prefers-reduced-motion. Glitch chỉ áp dụng trên desktop. Mobile chỉ đổi màu thanh HP sang đỏ + thêm warning text, không dùng CSS filter.

Open Questions

Mức drain mặc định −5 HP/giờ có hợp lý không?
Với max 1000 HP: nhóm im lặng hoàn toàn sẽ chết sau 200 giờ (~8 ngày). Nếu quá nhanh → nhóm thật chết oan. Nếu quá chậm → mất cảm giác urgency. Đề xuất: A/B test với −3 HP/giờ vs −5 HP/giờ trong 2 tuần đầu, theo dõi tỷ lệ nhóm chết và engagement rate.
Quyết định trước Slice 2 · ảnh hưởng toàn bộ cron logic
Tỷ lệ quy đổi Karma → HP nên là bao nhiêu?
Hiện tại 1 Karma = 10 HP, max 500 HP/lần sacrifice. Nếu Karma quá dễ kiếm thì Burning Karma mất ý nghĩa. Cần define rõ: Karma kiếm như thế nào (likes nhận được? deep post score?) trước khi set tỷ lệ sacrifice.
Phụ thuộc vào Karma system chung của platform · Confirm trước Slice 4
Museum nên public hay private theo từng nhóm?
Public museum tạo ra tính minh bạch và drama tốt — người ngoài vào xem "nhóm này chết vì ai". Private thì bảo vệ thành viên tránh bị chỉ trích. Đề xuất: admin chọn visibility khi tạo nhóm, default là public sau 30 ngày từ lúc chết.
