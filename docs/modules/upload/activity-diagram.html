Upload · Activity Diagram

Luồng xử lý — Upload

Trang này thể hiện đường đi của request qua các bước xử lý, bao gồm điểm quyết định và nhánh lỗi có thể xảy ra.

Luồng xử lý chính

Luồng này mô tả điều gì xảy ra khi request đi qua module upload: server kiểm tra token, validate input, áp rule nghiệp vụ, rồi ghi DB/Redis hoặc enqueue job.

Happy path đi thẳng xuống; nhánh đỏ bên phải là nơi request dừng sớm.

Validate DTO để tránh payload sai vào service. Bước này tồn tại để lỗi được phát hiện trước khi dữ liệu sai vào DB hoặc worker.

3

Service kiểm tra rule domain trước khi mutate. Bước này tồn tại để lỗi được phát hiện trước khi dữ liệu sai vào DB hoặc worker.

4
src/middlewares/shape.ts

Repository/provider thực thi side effect. Bước này tồn tại để lỗi được phát hiện trước khi dữ liệu sai vào DB hoặc worker.

Kết quả có thể

  • 200/201 success JSON
  • 400 validation/business error
  • 401 unauthorized
  • 403 forbidden
  • 404 not found
  • 500 provider/internal error
Happy path: token hợp lệ → input hợp lệ → service rule pass → DB/queue/provider thành công → response JSON.
